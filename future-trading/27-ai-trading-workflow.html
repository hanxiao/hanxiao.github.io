27 · 用 AI 武装交易：研究·回测·执行·复盘

第 26 章划清了 LLM 和 agent 在交易里能做与不能做的边界。这一章不再谈边界，谈装配：把检索（retrieval）、回测（backtesting）、执行（execution）和复盘（review）拼成一条你一个人就能跑起来的闭环工作流。重点不是"用上多少 AI"，而是在每个被 AI 加速的环节，把对应的纪律也加上——因为同一个工具，既能把你的研究效率抬高一个数量级，也能把你的自欺效率抬高一个数量级。

工作流全景：一条带闸门的闭环

把整个流程画成四段，每一段都配一道闸门（gate）——闸门不放行，下一段就不该开始：

            ┌──────────────────────────────────────────────┐
            ↓                                                │
  ① 研究 RESEARCH ── 闸门：信息是结构化输入，不是预测 ──┐    │
     LLM/RAG 压缩材料，生成假设                          │    │
            ↓                                            │    │
  ② 回测 BACKTEST ── 闸门：披露 N，打折，CPCV 看分布 ──┤    │
     在你自己的数据管线上跑，扣成本                       │    │
            ↓                                            │    │
  ③ 执行 EXECUTE ── 闸门：小仓位、手算对账、断网预案 ──┤    │
     先 paper 后 micro，再逐步放大                        │    │
            ↓                                            │    │
  ④ 复盘 REVIEW ── 闸门：实盘 vs 回测的偏离要能解释 ────┘    │
     归因、记录、检测 alpha 衰减 ──────────────────────────┘

每道闸门都是为了拦住一种用 AI 更快制造出来的假象。下面逐段拆。

① 研究：把 AI 当压缩器，不当预言机

研究阶段是 LLM 真正发力的地方，但只在输入端。你每天做嵌入、重排器、ReaderLM、late chunking，这套管线干的就是这件事：把非结构化材料压成可用结构。

研究阶段 AI 能稳定交付的：
  ✓ 财报/纪要/央行声明 → 结构化口径变化 + 关键变量
  ✓ 跨语言、跨来源聚合（交易所公告 + 持仓报告 + 新闻）
  ✓ 把你多年交易日志做成可问答的 RAG 知识库
  ✓ 把"自然语言策略描述"翻成代码骨架（仍需逐行验证）

研究阶段 AI 不交付的：
  ✗ "下一根 K 线" —— 召回率不是预测力
  ✗ 任何没碰过你数据的"绩效数字" —— 那是续写，不是测量

闸门很简单：研究阶段的产物是假设（hypothesis），不是结论。 AI 帮你把一周的阅读压到一小时，省下的时间应该投到第二段的验证里，而不是拿来多生成几百个未经检验的"信号"。

② 回测：被 AI 放大的那个 N，必须如实记账

这是整条工作流里最容易被 AI 毁掉的一段。原因在第 23、26 章已经点透：自动生成 + 自动回测，把试验次数 N 从人工的几十推到上万，而样本内最高夏普（Sharpe）被纯随机性抬高的幅度按 √(2·lnN) 增长。AI 不创造优势，它只是制造更多噪声的最大值，然后把那个最大值递给你。

所以回测段的纪律，必须随 N 一起升级。三个名字按严格程度排列：

通缩夏普 DSR（Deflated Sharpe Ratio, Bailey & López de Prado 2014）
  对裸夏普做"运气折扣"，校正项里直接含试验次数 N 和各试验夏普方差，
  并校正收益的偏度/峰度（胖尾会让显著性虚高）。N 越大，折扣越狠。

回测过拟合概率 PBO（Probability of Backtest Overfitting, Bailey 2014）
  不问"这个夏普显不显著"，问"样本内最优的那套，到样本外掉到中位数
  以下的概率有多大"。本质是给"挑了最好那个"这件事估一个翻车率。

组合净化交叉验证 CPCV（López de Prado 2018，《金融机器学习进展》）
  在 purged k-fold（训练/测试段之间 purge 重叠样本 + embargo 禁运期，
  消除前视/标签泄漏）之上，用组合方式生成【多条】样本外路径，
  得到夏普的【分布】而非单点 —— 你要的从来不是点估计，是 σ。

记住一条因果链：DSR、PBO、CPCV 这三件工具的折扣力度，全都随 N 单调变大。 这不是巧合——它们就是为"试得越多越要扣回去"而设计的统计闸门。AI 时代 N 爆炸，等于把这三道闸门的重要性同时拉满。

铁律照搬第 26 章：任何回测引擎的输出，都要用一个你手算得清的极简案例去对账。 工具会骗你不是因为恶意，是因为它的默认配置和你的假设不一致（持仓模式、静默截断、连续合约拼接）。AI 生成的回测代码尤其要逐行验证——它写得越流畅，你越容易跳过审查。

③ 执行：自动化省的是手速，不是判断

研究和回测都通过闸门后才进执行。这一段 AI 能做的是降低操作摩擦——挂单、监控、风控触发、移仓提醒都可以自动化（第 25 章），但它不替你承担方向判断和尾部风险。

执行段不可省的预案：
  - 断网/断电/API 限流时，仓位怎么办？（要有 server-side 止损兜底）
  - 滑点和延迟比回测差多少？先用 micro 合约量出来，别假设
  - agent 自动下单，必须有硬性的单日亏损上限和最大手数闸门
  - 任何"自动调参/自动换策略"的逻辑，等于在实盘里继续放大 N —— 禁止

过渡仍是第 23 章那四步：回测 → paper/前向测试 → micro 实盘 → 逐步放大。AI 没有缩短这条路，它只是让你更想跳过它。回测绩效是上限，实盘永远更差，预留这个折扣。

④ 复盘：让实盘去证伪回测

闭环的最后一段，也是 RAG 知识库真正长期复利的地方。把每一笔实盘记录回写进库，和回测预期逐笔对账：

复盘要回答的三个问题：
  1. 实盘绩效偏离回测了吗？偏多少？（分布层面，不是单笔）
  2. 偏离是【执行问题】（滑点/延迟/心理）还是【市场变了】（regime change / alpha 衰减）？
  3. 这个偏离，在我回测时的样本外路径分布里，属于正常波动还是异常？

注意第 3 问——这正是 CPCV 给你夏普分布的价值：有了样本外路径的 σ，你才能判断实盘的一段回撤是"还在预期内"还是"系统已经失效"。只有点估计的人，连这个问题都没法问。复盘的产物再喂回研究段，闭环才转起来。

把整条工作流当成一个 eval pipeline

退一步看：研究·回测·执行·复盘，结构上就是一个机器学习评估管线——数据进来、特征/假设、留出验证、上线、监控漂移。你每天为模型搭的那套 eval 纪律，几乎可以一比一搬到自己的交易上。

让一个好回测成立的纪律，和让一个好 ML eval 成立的纪律，是同一套——你已经精通它了，只是没把自己当成被评估的模型。

你给 RAG / agent 系统做评估时绝不会犯的错，在交易里都有精确的对应物：

  • 不在测试集上调参 = 样本外只用一次。 你知道反复看 held-out 集再改模型，held-out 就被污染成训练集了（你博士做对抗标签翻转，正是这件事的"攻击方"视角）。交易里这叫数据窥探（data snooping），解药就是 purged k-fold 与 CPCV——purge + embargo 去掉时序边界泄漏，组合路径把单点夏普变成一个 σ 有意义的分布。
  • 报告 best-of-N 必须暴露 N。 你扫超参再报最好那个，从不会假装只试了一次。交易里同一只野兽叫多重检验（multiple testing），折扣工具就是 DSR / PBO，校正项随 √(2·lnN) 增长。
  • 幻觉回测 = 没接数据管线的 eval 数字。 信息增益（information gain）为零的"夏普 2.3"，和一个没真正跑过测试集就报出来的 accuracy 是同构的——措辞流畅的随机数。

关键的不对称在这里：AI 把组件 overfit 放大了。 它把生成假设的边际成本压到零，于是 N 从几十涨到上万，样本内最高夏普虚高得更夸张，而样本外期望仍 ≈ 0。你的工具把 μ̂ 的估计成本压到了零，但没有改变 μ 本身有多小、σ 有多大——T 太小、N 太大时，μ̂ 几乎全是方差。你比谁都清楚这件事，别因为锤子是自己造的就忘了。把对待模型的评估纪律，原封不动地用在对待自己的回测上。

下面这个组件把上面那条不对称演示成可拖动的：把 N（一天试的策略数）从几十拖到上千——这正是 agent 自动搜策略的吞吐量——看样本内最高夏普如何被纯随机性抬起来，再看通缩夏普如何把它吞回去。注意样本外那条线始终贴着零。

本章要点

  • AI 交易工作流是一条带闸门的闭环：研究 → 回测 → 执行 → 复盘，每道闸门拦住一种被 AI 更快制造出来的假象。
  • 研究段：AI 是输入端压缩器，产物是假设不是结论；召回率不等于预测力。
  • 回测段：N 被 AI 放大到上万，纪律必须同步升级——DSR 给裸夏普打运气折扣、PBO 估翻车率、CPCV（López de Prado 2018）给夏普一个分布；三者的折扣力度都随 N 单调变大（Bailey & López de Prado 2014）。一切引擎输出用手算极简案例对账。
  • 执行段：自动化降的是操作摩擦，不替你扛方向和尾部风险；断网/止损兜底要硬，禁止在实盘里自动换策略（那是继续放大 N）。
  • 复盘段：用实盘去证伪回测；有了 CPCV 的样本外路径分布，才能判断一段回撤是"预期内"还是"系统失效"。
  • 一句话：让一个好回测成立的纪律，就是让一个好 ML eval 成立的纪律。 AI 放大的是组件 overfit，不是优势。
