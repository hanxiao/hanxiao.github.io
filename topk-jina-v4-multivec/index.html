How it works

1. Multi-vector embedding. Instead of pooling an input into a single vector, jina-embeddings-v4 emits an N×128 matrix — one 128-d vector per text token, or per image patch. A short query is ~5–10 vectors; an image is a few hundred patch vectors.

2. TopK matrix field + MaxSim. Each document's matrix is stored in a TopK multi_vector_index with metric="maxsim". Scoring sums, over each query vector, its best match against any document vector — preserving fine-grained signal that single-vector search averages away.

3. One cross-modal index. Text and image vectors share the same space, so a text query ranks images and passages together. The modality and tag controls use TopK metadata filtering fused into the same vector query.
