Search has mostly improved by training harder.
Bigger encoders, cleaner data, faster indexes, stronger rerankers.

Recent LLMs found a second axis: compute at inference

Test-time scaling: rather than a bigger model, the same model does more work per query, along a smooth cost-quality curve.

Having a bot think for just 20 seconds in a hand of poker got the same performance boost as scaling up the model by 100,000x and training it for 100,000 times longer.Noam Brown, OpenAI, 2024
Fun fact: search has always lived on that axis.
Embed, retrieve, rerank, expand, fuse. None of it happens at training time. All of it runs after the user presses Enter.

Four demos, all training-free

Each one gets better performance or a new capability just by spending more compute at test time.

01
Programs that transfer
An LLM writes retrieval programs over one frozen encoder. They transfer to model families they never saw.
02
Image tags for free
A frozen retrieval model becomes an open-vocabulary image tagger.
03
One call, no index
One listwise reranker call over a whole page replaces chunking, embedding and indexing.
04
Agent-built pipelines
An agent assembles its own search pipeline from local tools, per query.

Three ways to spend compute on a frozen model

The weights are the same in all three. They differ only in what enters the computation.

A
Deeper pass
Read more of the pass you already ran: every token or patch vector, not only the pooled one.
New information: recovered from inside the pass
B
More passes
Run the encoder again on new views: split the document, crop the image, re-encode.
New information: taken from the input
C
Calibration
Transform the vectors you already have: whitening, label propagation, optimal transport.
New information: none

Calibration does not move accuracy

The 2024 to 2026 training-free literature bets on calibration. On this encoder every calibration lever is flat or collapses.

Only new information moves accuracy.
Calibration rearranges what the model has already seen. Patches and crops give it more to look at.

For a single page, drop the index

An index pays off over many queries. A page lives for one visit, so skip chunk, embed and index, and run one listwise pass over the whole page.

No index, no vector store, no chunk database.

jina-reranker-v3.5 scores a 53-chunk page in 143 ms per call, against 4,194 ms for jina-reranker-v2-base-multilingual.

Answers are highlighted in place, and the page keeps its own layout.

dataroom: spend a token budget on building a corpus

A local model runs search, read and write in a loop until the knowledge sits in one cited .zip. It stops at a measured coverage floor.

Stops on outcome, not on a fixed token count.

The live job page shows coverage, token usage and the tool-call distribution.

The .zip goes to searchbox or to a frontier model.

knowledge-graph: hard questions as a private verifier

If one grep finds the answer, every method scores the same. Agentic search needs questions that force several hops.

Turn the corpus into subject-predicate-object edges.

Walk paths of length 2 and 3, hide the bridge entities, ask for the endpoint.

What the four demos share

Same frozen models throughout. Only the inference budget, and where it is spent, changes.

Training-free
Programs, tags, listwise ranking and agent pipelines all run on frozen weights.
Compute buys quality
+0.24 in-search from programs. A tagger from a retrieval model. A whole index replaced by one call.
New information converts
Patches: +0.37 mAP for free. Crops: +0.075 for 14x. Calibration: about zero.
Check out of domain
+0.24 in search became −0.016 on held-out tasks. Cheap structure and private verifiers survive the check.

Where to spend it in an Elasticsearch stack

Each lever maps to something you can configure today.

retriever · rrf
Fuse rankings
Combine lexical and dense results with the rrf retriever. RRF is what the program search rediscovered.
retriever · text_similarity_reranker
Rerank the top-k
Add a listwise reranker with the text_similarity_reranker retriever and let the candidates see each other.
field · semantic_text
Score chunks
With semantic_text chunking, rank documents by their best chunk instead of one pooled vector.
agents · budget
Budget the agent
Give agents a token budget and a private multi-hop eval before giving them more tokens.
Search has always been test-time compute. Spend it where new information enters.
